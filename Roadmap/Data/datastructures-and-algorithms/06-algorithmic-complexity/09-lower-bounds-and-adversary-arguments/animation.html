Lower Bounds & Adversary Arguments

Why no comparison sort beats Θ(n log n): the n! outputs force a tall decision tree

Comparison Decision Tree

comparison (internal node) leaf = sorted permutation traced root→leaf path
Comparison model only. This bound counts comparisons between elements. Sorts that read the keys' digits or bits instead — counting sort, radix sort, bucket sort — are not comparison sorts, so they sidestep this tree and can run in O(n) on suitable keys.

The Lower Bound, Computed

Information-theoretic argument. A comparison sort of n items must distinguish all n! possible orderings, so its decision tree needs ≥ n! leaves. A binary tree with L leaves has height ≥ ⌈log₂ L⌉, and height = worst-case comparisons. Therefore every comparison sort makes ≥ ⌈log₂(n!)⌉ = Θ(n log n) comparisons in the worst case. No cleverness escapes it.

Adversary for Finding the Maximum

Why n−1 Comparisons Are Forced

Adversary argument. An element can be the maximum only if it has never lost a comparison. To name the max with certainty, the algorithm must reduce the set of "could-still-be-max" candidates from n down to 1. Each comparison produces at most one new loser, so the adversary — answering consistently to keep candidates alive — forces ≥ n−1 comparisons. Tournament-style algorithms match it exactly.
