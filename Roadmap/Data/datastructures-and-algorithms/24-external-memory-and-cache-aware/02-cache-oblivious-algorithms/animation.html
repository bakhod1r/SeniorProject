Matrix transpose: naive loops vs recursive (cache-oblivious)

An n×n matrix is stored row-major in memory, split into blocks of B cells (a "cache line"). Reading element (r,c) of the source and writing (c,r) of the destination touches whatever block that address falls in. The naive double loop walks the source row-by-row but writes the destination column-by-column — those column writes jump across many blocks → cache misses. The recursive version splits the matrix into quadrants until a sub-block fits in cache, so both reads and writes stay local. Watch the I/O (block-miss) counters.

Why recursion wins at every level

The recursive transpose obeys the recurrence Q(n) = 4·Q(n/2) + O(1) until a sub-matrix fits in a block, giving Θ(n²/B) transfers — optimal, and the same code is optimal for L1, L2, L3 and RAM at once because it never bakes in a particular B. A cache-aware tiled version can be a constant factor faster on one tuned level, but you must tell it the tile size for that level. Cache-oblivious trades a little constant factor for portability across the whole hierarchy. Try different B values above: the recursive miss count tracks Θ(n²/B) without any change to the algorithm.
