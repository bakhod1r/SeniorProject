How it works

Reverse order is a gift: the heads of both lists are the ones place, so you add left-to-right and the carry always flows forward into the next node.

One pass, no number ever reconstructed (which would overflow for long lists). Time O(max(m, n)), extra space O(1) beyond the result list. The loop also runs while carry > 0, which is what grows 999 + 1 into a 4-digit answer.
